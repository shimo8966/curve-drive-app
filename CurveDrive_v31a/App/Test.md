計画だけの保存と、施工開始後の実測入力を分けて確認している。

合計269件合格。C#5互換のコンパイルはMonoでも警告をエラー扱いにして成功。
画面・通信検査の合格は、実際のJW_CADでの動作確認とは別に数える。

主な確認事項：

- 初期の実測は0件。計画線だけで作成、プレビュー、DXF出力、JSON保存ができる。
- 計画だけの状態でブラウザーとBridgeを終了・再起動しても、実測0件のまま再開する。
- 施工開始後は、最初の実測を0.5mなど実際に測った延長から入力できる。実測した0mも登録できる。
- 最初の実測は点のみを作図し、未測定の0mから接続線を作らない。2点目から実測同士を結ぶ。
- 計画だけの照合結果を、最初の実測が確認済みという表示に流用しない。
- 深さ (m) は別の値としてJSON・CSVへ保持する。上下ズレ (mm) へ変換せず、図面の高さにも使用しない。
- 実測は1点ずつ送信し、前点と作業登録を照合する。重複や未送信測点を飛ばした追加を防ぐ。
- 古い作業番号の連携処理を拒否しても、現在の登録を停止・上書きしない。
- 作業中にJSON・CSVを読み込んで入力を置き換えた場合は、入力確認へ戻す。実測0件のバックアップも新しい図面として準備できる。

## Windows上のJW_CADによる最終検証

最終実行記録：https://github.com/shimo8966/curve-drive-app/actions/runs/43952124071

|対象|最終結果|
|---|---|
|公式JW_CAD 8.25a|合格|
|公式JW_CAD 10.03.8|合格|

両方のバージョンで一連の実行が成功し、次の項目を確認した。

- Windows Server 2022、.NET Framework、表示状態のEdgeから、専用図面を作成してJW_CADを起動する。
- 実測0件で発進点の印と計画基準を自動照合し、計画だけの準備を完了する。
- 計画DXFと入力JSONを保存し、ブラウザーとBridgeを再起動して実測0件の状態を維持する。
- 最初の実測0.5mを点として追加し、続く1.0mを実測同士の線で接続する。
- 任意の深さを別に記録し、上下ズレとの分離、保存、再開を確認する。
- 別の参照フォルダーから作業用フォルダーと固有の連携ファイルを選択し、追加後の測点と線を読み戻す。
- 座標移動と方向角を持つ左右カーブの位置を独立した計算と照合し、元の計画線を保持する。
- JW_CADを終了した状態からの自動起動と、従来方式の互換を確認する。
- 古い連携ファイルが選択・フォーカス済みの一覧でも、現在の作業のファイルだけを実行する。
- 古い作業番号のBATを実際に実行しても、現在の登録と図形を保持して拒否する。

配布時は、最終Windows実行でビルドしたEXEを使用する。
C#4ファイルとapp.htmlを、同じ実行のNativeSource.jsonにあるSHA256と照合する。
通常のアプリに画面全体へのキー・マウス入力はない。旧方式の右クリック検査では、検査専用プログラムが架空図面上のマウスを操作する。

## 検証の範囲

- 利用者のWindows 11、会社独自の設定、実際の現場図面では未検証。
- 自動方式は、入力から作る専用DXFを使う。既存本番図面の更新や、JWで手描きした加筆の自動保存は対象外。
- JWへの逐次追加・読み戻しは平面の点と線。上下ズレは最新DXFの縦断に反映する。深さはJSON・CSVの記録用で、自動変換しない。
- 過去の実測や計画の訂正は、入力を見直して新しい専用図面を作成する。既存図形の削除・置換は行わない。
- 旧方式のv8の英語環境では、保存済みの架空JWWを使う。v8の名前を付けて保存は合格項目に含めない。通常の自動方式では、この保存操作を使わない。

## 開発者向け

C#はBridge.cs、AutoBridge.cs、CadContext.cs、CadNative.csを一緒にビルドする。
/noconfig、C#5、System.dll、System.Core.dll、System.Web.Extensions.dllを明示する。

```
node --test tests/frontend.cjs
python tests/bridge.py --exe Bridge.exe --mono /path/to/mono -v
python tests/batch.py
node tests/browser.cjs
node tests/guide.cjs
node tests/recovery.cjs
```

ブラウザー検査はPlaywright、CURVE_MONO_PATH、CURVE_CHROMIUM_PATHが必要。
AutoTests、NativeTests、ListTestsは同じC#ソースにtests内の同名ファイルを追加し、エントリポイントを指定する。
固定ポートを使う検査は直列で実行する。通常利用にNode、Python、Monoは不要。
