# v3.1 検証結果

Windows Server 2022、.NET Framework、表示状態のMicrosoft Edge、公式JW_CAD 8.25a・10.03.8で検証した。
両バージョンで次の一連の操作が成功した。利用者の提供ファイルを使わず、架空の図面だけで実施した。

- 入力画面のボタンから専用DXFを作成し、JW_CADを起動。
- 前回と違うフォルダーから、今回の作業フォルダーと固有BATを自動選択。
- 図面の2つの印、計画基準、実測終点から発進点を自動登録。利用者のCAD操作や点クリックは不要。
- 実測入力のEnterからCADへの追加、点と接続線の読み戻し、次の入力欄へのフォーカス。
- 直線の10.5m/左20mm、11m/右20mm。PC保存データからブラウザーの入力を自動復元して再開。
- 発進X=1000m、Y=-2000m、方向30度、直線・左R100・直線・右R80・直線の計画で、40m/右20mmと49m/左30mmを照合。独立した円中心による計算と0.05mm以内で一致。
- JW_CADをすべて終了した状態から、記憶した実行ファイルの場所とPC保存入力を使って再開。
- 元の計画線100本、実測点数、接続線を確認。保存はJSONと最新DXFの両方を確認。
- 従来方式の実際の発進点右クリック、JWW保存後の再開、再実行による追加、重複防止も確認。

## 検証の範囲

- 利用者のWindows 11、会社独自の設定、実際の現場図面では未検証。
- 自動方式は入力から新しく作る専用DXFを使う。既存本番図面の更新や、JWでの手描き加筆の自動保存は対象外。
- JWへの逐次追加・読み戻しは平面の点と線。縦断は入力から生成する最新DXFに保存する。
- 過去の実測の訂正は入力を見直し、新しい専用図面を作成する。既存図形の削除・置換は行わない。
- 旧方式のv8の英語環境では、あらかじめ保存した架空JWWで再開を検証。v8の名前を付けて保存は合格項目に含めない。新しい自動方式ではこの保存操作を使わない。

## 開発者向け

C#はBridge.cs、AutoBridge.cs、CadContext.cs、CadNative.csを一緒にビルドする。
/noconfig、C#5、System.dll、System.Core.dll、System.Web.Extensions.dllを明示する。

```
node --test tests/frontend.cjs
python tests/bridge.py --exe Bridge.exe --mono /path/to/mono -v
python tests/batch.py
node tests/browser.cjs
node tests/guide.cjs
```

ブラウザー検査はPlaywright、CURVE_MONO_PATH、CURVE_CHROMIUM_PATHが必要。
AutoTests、NativeTests、ListTestsは同じC#ソースにtests内の同名ファイルを追加し、エントリポイントを指定する。
固定ポートを使う検査は直列で実行する。通常利用にNode、Python、Monoは不要。
